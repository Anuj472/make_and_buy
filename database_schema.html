Actual Data Models

Database schema mapping exactly to the CSV datasets in the project.

1

Active Indents (Orders)

active_indents.csv

Contains the customer demand, deadlines, and financial constraints for specific items.

Column Name Description Data Type
order_id Unique identifier for the customer order. PK : String
item_id The product requested in this order. FK : String
order_quantity Total number of units required. Integer
delivery_period_days Maximum allowed days to fulfill the order. Integer
ld_rate_per_week Liquidated Damages (penalty) rate applied per week late. Float
max_ld_percentage Maximum cap on the total penalty. Float
contract_value_per_unit The revenue generated per unit sold. Float
2

Item Master (Components)

mto_item_master.csv

The catalog of all opto-electronic assemblies, containing material and labor base costs.

Column Name Description Data Type
item_id Unique identifier for the product/assembly. PK : String
description Human-readable name of the product. String
is_critical_component Flag indicating if it must be made in-house for strategic reasons. Boolean
raw_material_cost_per_unit Cost of physical materials required to build one unit. Float
expected_scrap_percentage The average percentage of units ruined during production. Float
labor_cost_per_unit Direct human labor cost to build one unit. Float

Machine Capacities

machine_capacities.csv

Details available in-house machine capabilities and operating costs.

Column Name Description Data Type
machine_id Unique identifier for a piece of factory equipment. PK : String
available_yearly_hours Total theoretical hours the machine can run. Float
existing_wip_hours Hours already booked by work-in-progress. Float
operating_cost_per_hour Overhead cost per hour to run the machine. Float

Production Routings (Make Steps)

production_routings.csv

Maps out the step-by-step process of how to build an item internally.

Column Name Description Data Type
item_id The product being built. FK : String
operation_sequence The order of the manufacturing step (e.g. 10, 20, 30). Composite PK : Integer
machine_id The machine required for this step. FK : String
setup_hours Fixed time required to prepare the machine (regardless of batch size). Float
run_hours_per_unit Variable time required to process a single unit on the machine. Float

external_supplier_quotes.csv

The catalog of available outsourcing options and their costs/risks.

Column Name Description Data Type

vendor_price_per_unit Base price to buy one unit. Float
vendor_lead_time_days Number of days from order placement to delivery. Integer

incoming_qa_hours_per_unit Time required to inspect bought items upon arrival. Float
incoming_qa_cost_per_unit Cost to inspect bought items upon arrival. Float

Vendor Reliability Score System

The Vendor Reliability Score (VRS) transforms qualitative supplier risk into a quantitative metric used by the MILP optimizer to adjust effective procurement costs.

VRS = (W₁ × Quality) + (W₂ × Delivery) + (W₃ × Cost) + (W₄ × Responsiveness)

The final score ranges from 0 to 1. In the optimization engine, the baseline purchase cost is divided by the VRS, dynamically increasing the effective cost of dealing with unreliable vendors.

W₁ = 0.40

🛡️ Quality Score

Measures the historical defect rate of incoming parts from the vendor.

Calculation:
(Total Units Accepted) / (Total Units Supplied)
W₂ = 0.30

⏱️ Delivery Score

Measures adherence to promised lead times to prevent production stalls.

Calculation:
(Orders Delivered On-Time) / (Total Orders Placed)
W₃ = 0.20

💵 Cost Consistency

Evaluates the supplier's tendency to suddenly escalate agreed prices.

Calculation:
1 - (Price Escalation Instances / Total Orders)
W₄ = 0.10

💬 Responsiveness

Scores the supplier's agility in communication and issue resolution.

Calculation:
1 - (Avg Response Time / Max Acceptable Time)
