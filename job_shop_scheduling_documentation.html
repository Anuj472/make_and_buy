Overview: What is Job Shop Scheduling?

How the system turns Make-or-Buy decisions into an exact minute-by-minute factory schedule

🏭

The Big Picture (The 2-Stage Manufacturing System)

Bridging strategic planning with daily shop-floor machine dispatches

1
Stage 1: The Make vs. Buy Optimizer (MILP / PuLP)

Looks at yearly customer orders, machine hours, and supplier prices. It decides which orders to manufacture in-house and which orders to outsource to vendors.

2
Stage 2: The Job Shop Scheduler (Google OR-Tools CP-SAT)

Takes only the orders decided for in-house manufacturing (Make_In_House_Qty > 0). It looks at the step-by-step routing operations (e.g. Milling → Polishing → Coating → Testing) and calculates the exact start and finish times for every job on every machine without any machine conflicts.

3
Stage 3: The Calendar Engine & Shop Floor Gantt Chart

Converts the solver's working minutes into real calendar dates and shift hours (8:00 AM to 6:00 PM, Monday to Saturday, skipping Sundays), allowing supervisors to filter by machine, month, and week, or download a CSV dispatch sheet.

The Input Variables & Data Tables

Every CSV file, column, and data point used by the Job Shop Scheduler

📋

1. Order & Demand Data (Final_Make_Buy_Decisions.csv / active_indents.csv)

Tells the scheduler which customer jobs need to be made, how many units, and when they are due

Data Attribute Description Data Type Example How the Scheduler Uses It
Order_ID Unique identifier for the customer order. Text MOD-ORD-1002 Labels the job bar in the Gantt chart and creates distinct variables.
Item_ID Product part code being made. Text IOL-OPT-002 Matches with the production routings file to get the list of manufacturing steps.
Make_In_House_Qty Quantity assigned to be made in-house. Integer 24 units If 0, this order is skipped. If > 0, this quantity is multiplied by run hours per unit.
Delivery_Period_Days Target delivery deadline in business days. Number 180 days Converted into working minutes to calculate whether a job is on-time or tardy.
ld_rate_per_week Liquidated Damages penalty rate per week late. Percentage 0.5% (0.005) Measures financial penalty if the job finishes after the due date.
Due Date in Working Minutes Formula:
due_date_minutes = Delivery_Period_Days * 600 minutes
// Explanation: Since the plant runs 10 hours a day, 1 working day = 10 hours * 60 mins = 600 mins.

🔄 Where this data comes from:

  • ERP Sales Module / Indents: Customer sales orders or production indents provide the quantity and agreed delivery dates.
  • Stage 1 Optimizer Output: The Make vs. Buy optimizer generates Final_Make_Buy_Decisions.csv saving the recommended quantities.
⚙️

2. Production Routings (production_routings.csv)

Defines the step-by-step recipe, machine order, setup time, and run time for each item

Data Attribute Description Data Type Example How the Scheduler Uses It
item_id Part code matching the order. Text IOL-OPT-002 Links the routing recipe to the active order.
operation_sequence The order in which steps must happen. Integer 10, 20, 30 Enforces strict order: Step 10 must finish before Step 20 can start.
machine_id The required workstation/equipment. Text CNC_MILL Tells the solver which machine calendar to assign this task to.
setup_hours Fixed time to clean, tool, and calibrate machine. Hours 1.0 hr Required once per batch, regardless of whether making 1 unit or 100 units.
run_hours_per_unit Machining time to produce 1 finished piece. Hours/Unit 2.48 hrs Multiplied by Make_In_House_Qty to get total production run time.
Total Task Duration Formula (in Minutes):
total_hours = setup_hours + (run_hours_per_unit * Make_In_House_Qty)
duration_minutes = ceiling(total_hours * 60)

// Example for Order 1002 (24 units on CNC_MILL):
total_hours = 1.0 + (2.48 * 24) = 1.0 + 59.52 = 60.52 hours
duration_minutes = ceiling(60.52 * 60) = 3,632 minutes (approx. 6 working days)

🔄 Where this data comes from:

  • Manufacturing Engineering (PLM): Industrial engineers perform time-and-motion studies to define standard setup and cycle times for each part.
  • Routing Master in MES: Contains the approved sequence of operations for quality compliance.
🛠️

3. Machine Infrastructure (machine_capacities.csv)

Lists available equipment, existing commitments, and hourly running rates

Data Attribute Description Data Type Example How the Scheduler Uses It
machine_id Name of the machine work-center. Text LENS_POLISHER The physical resource that can only process 1 job at a time.
available_yearly_hours Total operational hours available per year. Hours 1,000 hrs Ensures the total factory load does not exceed physical equipment limits.
existing_wip_hours Hours already busy with previous jobs. Hours 20 hrs Represents ongoing background work before new jobs can start.
operating_cost_per_hour Direct cost to run the machine per hour. Currency ₹800 / hr Used to calculate total machine operating expense.

The Core Rules & Constraints

The 3 unbreakable physical laws enforced by the scheduling solver

➡️

Rule 1: Step-by-Step Sequence (Precedence Constraint)

A later step cannot start until the earlier step is completely finished

In manufacturing, you cannot coat a lens before it is cut, and you cannot test it before it is polished. For every order, the solver guarantees that:

Step_2_Start_Time >= Step_1_End_Time
Step_3_Start_Time >= Step_2_End_Time

In the code: model.Add(start_var >= previous_task_end)

🚫

Rule 2: No Machine Collisions (Disjunctive Resource Constraint)

A machine can only work on one order at any single minute

If Order A is currently being processed on the COATING_CHAMBER, Order B must either finish before Order A begins, or wait until Order A is completely removed from the chamber. Two jobs can never occupy the same machine at the same time.

For any Job A and Job B on Machine M:
Either (Job A Ends <= Job B Starts) OR (Job B Ends <= Job A Starts)

In the code: model.AddNoOverlap(machine_intervals[machine_id])

⏱️

Rule 3: Working Hours & Weekend Maintenance

Machines do not run 24 hours a day without stops

Production only occurs during active shift hours. Work is automatically paused during nights and Sundays:

1 Working Day = 10 Working Hours (8:00 AM to 6:00 PM) = 600 Minutes
1 Working Week = 6 Days (Monday through Saturday) = 3,600 Minutes
Sunday = Plant Shutdown / Preventive Maintenance (0 minutes)

The Optimization Algorithms Explained Simply

How Google OR-Tools CP-SAT solves the puzzle compared to other methods

🧠

What is Google OR-Tools CP-SAT?

A Constraint Programming solver built on modern SAT (Satisfiability) technology

Think of Job Shop Scheduling like solving a giant Sudoku puzzle:

  • You have 5 machines and 100 operations that all need time slots.
  • If you schedule Job 1 early on the CNC Mill, it might delay Job 2, which then misses its delivery due date.

Instead of guessing, Google OR-Tools CP-SAT uses mathematical logic:

🔍 How the Solver Thinks:

  • Interval Variables: Treats each task as a solid block of time with a Start, Duration, and End.
  • Deduction (Edge Finding): If 3 jobs together need 20 hours on the Lens Polisher, and there are only 22 hours left before the weekend, the solver instantly deduces which job must go first without testing wrong combinations.
  • Conflict Learning: When an arrangement hits a dead end (e.g. causes a job to be late), the solver remembers why that failed and never tries that pattern again.
⚖️

Why Google CP-SAT instead of Traditional MILP or Simple Rules?

Comparing common scheduling methods in manufacturing

Method How It Works Pros Cons / Why It Struggles
Google OR-Tools CP-SAT
Used in our App		 Uses Interval variables and Boolean logic specifically designed for scheduling. Finds mathematically proven optimal or near-optimal schedules in 5 to 30 seconds. Handles non-overlap naturally. Requires discrete integer minutes (no continuous fractions).
Standard MILP (PuLP / Linear) Uses "Big-M" formulas ($y = 0$ or $1$) to force one job before another. Great for Stage 1 (Make vs. Buy high-level volume choices). Terrible for fine-grained scheduling! The solver takes hours or days because the math formulas are too loose.
Simple Dispatch Rules (FIFO / Shortest First) Greedy rules: "First Come First Served" or "Shortest Job First". Instant calculation (under 1 second). Very poor results! Creates big idle gaps on machines and causes critical orders to finish weeks late.
Genetic Algorithms (AI Heuristics) Simulates evolution by shuffling schedules and picking the best survivor. Good for massive factories with 10,000+ machines. Cannot guarantee that a schedule is truly optimal, and can get stuck in bad local traps.

The Optimization Goals (What the Solver Minimizes)

Different business goals change how the solver arranges jobs on the timeline

⏱️

Goal 1: Minimize Makespan (Total Factory Time)

Finish all jobs in the fewest total working days

The Business Objective: Clears the factory floor as fast as possible. This frees up equipment so the company can take on new customer contracts sooner.

Makespan = End_Time_of_the_Very_Last_Job_in_the_Plant
Goal: Minimize(Makespan)
Real Example in App: Under this goal, the solver compacted all in-house orders to finish in 108 working days.
📅

Goal 2: Minimize Tardiness (Meet Customer Due Dates)

Deliver orders on time and avoid late penalty damages

The Business Objective: When customer satisfaction and contracts are the #1 priority. Instead of trying to finish everything fast, the solver prioritizes orders with urgent deadlines first.

Lateness = Job_Finish_Time - Job_Due_Date
Tardiness = max(0, Lateness) // If early, tardiness is 0

Goal: Minimize(Sum_of_All_Tardiness_Days)
Important Catch Explained: In this goal, the primary metric is total late days, NOT makespan. The schedule might take longer in total calendar days because machines prioritize urgent orders rather than packing tasks as tightly as possible.
🔄

Goal 3: Minimize Setup & Changeover Costs

Group similar jobs together to avoid washing and recalibrating machines

The Business Objective: In optical lens manufacturing, switching between lens materials (e.g. Acrylic to Silicone) or optical coatings requires flushing chemical lines and resetting tooling (up to 6 hours of downtime).

Goal: Minimize(Total_Setup_and_Changeover_Hours)
// Jobs using the same material or tooling are scheduled back-to-back.

Inputs Required to Add This Goal:

  • Changeover Matrix Table: A matrix showing the cleaning/setup time required when switching from Product A to Product B.
  • Sequence Variables: The solver needs to decide the order of jobs on each machine to find the shortest total transition path.

Calendar Math & Shift Splitting

How the system turns raw working minutes into real factory calendar dates

📆

How Working Minutes Become Calendar Dates

Understanding the factory shift schedule

Parameter Value Why It Matters
Shift Start Time 8:00 AM Every working day starts at 8 AM.
Shift End Time 6:00 PM Every working day ends at 6 PM (10 hours total).
Daily Minutes 600 minutes / day 10 hours * 60 minutes = 600 minutes.
Working Days Monday through Saturday (6 days) Factory operates 6 days a week (3,600 minutes/week).
Sunday Plant Closed The calendar logic automatically jumps over Sundays!

🧩 What happens if a job takes 25 hours (1,500 minutes)?

A 25-hour job cannot be done in one day. The system splits it into 3 segments:

  • Day 1 (Monday): Works 10 hours (8:00 AM to 6:00 PM) → 15 hours remaining.
  • Day 2 (Tuesday): Works 10 hours (8:00 AM to 6:00 PM) → 5 hours remaining.
  • Day 3 (Wednesday): Works 5 hours (8:00 AM to 1:00 PM) → Finished!

The Gantt chart shows these as continuous bars on each day, perfectly respecting factory opening and closing times.

Step-by-Step Practical Example

Following a single real order through the entire scheduling math

🔍

Order MOD-ORD-1002 (Part: IOL-OPT-002, 24 Units)

See exactly how the numbers flow through the formulas

1
Step 1: Check In-House Decision

The Make-or-Buy optimizer decided: Make_In_House_Qty = 24 units. Because this is > 0, it enters the Job Shop Scheduler.

2
Step 2: Calculate Durations for Each Machine Operation
  • Op 10 (CNC_MILL): Setup = 1.0 hr, Run = 2.48 hrs/unit.
    Total = 1.0 + (2.48 * 24) = 60.52 hrs → 3,632 minutes (approx. 6.05 working days).
  • Op 20 (COATING_CHAMBER): Setup = 5.3 hrs, Run = 1.57 hrs/unit.
    Total = 5.3 + (1.57 * 24) = 42.98 hrs → 2,579 minutes (approx. 4.30 working days).
  • Op 30 (ASSEMBLY_STATION): Setup = 1.0 hr, Run = 0.16 hrs/unit.
    Total = 1.0 + (0.16 * 24) = 4.84 hrs → 291 minutes (approx. 0.48 working days).
3
Step 3: Enforce Precedence in Solver

The solver assigns Op 10 starting at Minute 0. It finishes at Minute 3,632. Op 20 cannot start before Minute 3,632. Op 30 cannot start before Op 20 finishes.

4
Step 4: Check Customer Due Date

Contract allows 180 days = 108,000 working minutes. Total time needed is 6,502 minutes. This job easily finishes on time, so its Tardiness penalty = 0!
